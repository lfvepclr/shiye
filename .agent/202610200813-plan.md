## 一、接下来的计划

### P0-A 数据组织第 1 步：识别结果落盘（0.5d）

**为什么**：识别结果花钱买来、无法重建，现在只存在 SQLite。DB 损坏/换机器 = 结果全丢，也无法逐页对账。

- 识别成功后写 `{data_dir}/g/<gid>/pages/<pid>/ocr/result.json`：
  ```json
  { "version": 1, "w": 1387, "h": 2000, "source": "api|cache", "ocr_ms": 2140, "blocks": [ … ] }
  ```
- DB 保持为查询索引，文件是快照；两者同事务语义：先写文件再提交事务，写文件失败只记日志
- 命中缓存的页也要写（`source: "cache"`），保证每页都有快照
- 新接口 `GET /api/v1/pages/{id}/result` 返回该 JSON（鉴权同设备）
- 验收：11 页 fixture 跑完后每页都有 `result.json`；`source` 分布与缓存命中数一致；删掉 DB 重建后块仍可从文件恢复（提供 `--reindex` 或暂只做人工恢复脚本）

**涉及**：`storage.rs`（路径）、`render.rs`（store_blocks 前写）、`routes/pages.rs`（新接口）

### P0-B 数据组织第 2 步：派生物分目录（0.5d）

**为什么**：备份只想备原件，清理只想清预览；现在 `raw/edit/disp/thumb` 混在一层。

```
pages/<pid>/
├── raw.jpg            # 原件
├── edit.jpg           # 规整后
├── preview/1600.jpg   # disp
├── preview/320.jpg    # thumb
├── ocr/result.json
└── fig/fig_x.png
```

- `ocr_cache` 根目录从 `{data_dir}/ocr/` 改为 `{data_dir}/cache/ocr/`（语义：可整目录删）
- 旧数据兼容：读取时先找新路径、再回退旧路径；写一律写新路径（不做一次性迁移，避免启动阻塞）
- 验收：新上传的页落在新结构；旧页仍能出图；删掉 `cache/` 后业务功能不受影响（只是重新识别）

**涉及**：`storage.rs`、`routes/share.rs`（取图）、`render.rs`、`routes/pages.rs`（写派生图）

### P0-C 修复原文叠加文字溢出（0.5d）

**现状**：206 块里，390px 有 7 块、1080px 有 36 块文字被裁（`scrollHeight > clientHeight`）。
字号目前按「单行高度中位数」估，多行块必然多一行。

- 方案：单块自适应——按 bbox 高度 / 行数试排（`line-height 1.6~1.85`），超出则 0.95 步进缩字号，下限 0.9×；仍溢出则允许 `overflow: visible`（宁可压到邻块，不可吞字）
- 验收：两档宽度下 `clipped = 0`，且字号与相邻块差异 ≤ 15%（避免大小不一）

**涉及**：`viewer/index.html` 的 `pageFontCqw` / `overlayBlock`（注意：改完必须重编译，见问题 3）

## 三、已知问题

1. **文字溢出块**：390px 7/206、1080px 36/206（详见 P0-C）。
2. **Word 保真度**：表格列宽、插图位置与原页仍有偏差（`samples/out/compare-1p.png`）；公式行内基线偶有错位。
3. **Viewer 内嵌**：`include_str!` 编译进二进制，改 HTML 不重编译看不到效果——今天已踩过一次。
4. **缓存淘汰只有条数上限**（500 条），无字节上限；多进程部署时 `prune` 无跨进程锁（当前单进程，可接受）。
5. **身份模型**：`X-Device-Id` 即身份，拿到别人的 device id 就能读写其文档；分享链接是唯一对外的只读凭证。公开部署前需评估是否需要真正的账号体系。
6. **预览与原件同层**：备份/清理边界不清（P0-B 解决）。
7. **分享页性能只在 loopback 测过**：LCP 72~84ms 是本地数字，未测 4G / 弱网。
8. **`blocks.json` 一直没实现**：设计文档 §6.2 提到，代码里只有 DB（P0-A 解决，文件名统一叫 `ocr/result.json`）。
