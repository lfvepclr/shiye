# 多用户隔离说明（2026-10-20）

> 结论：没有登录体系，**每台设备一个随机 UUID 就是身份**。服务端所有 `/api/v1` 查询都按设备过滤，跨设备访问一律 404；唯一的跨设备通道是分享 token（只读、可撤销、可过期）。本次补齐了逐路由审计与回归测试，未发现越权读写路径。

---

## 1. 身份模型

| 环节 | 做法 |
| --- | --- |
| 生成 | 客户端首启 `util.generateRandomUUID(false)`，UUIDv4（122 bit 随机），存 `preferences`（键 `device_id`），此后不变 |
| 传输 | 每次请求带 `X-Device-Id`；不放在 URL/body，避免落进访问日志与分享链接 |
| 校验 | 服务端 `Uuid::parse_str` 校验，缺失或非法 → **401**，不做任何兜底默认值 |
| 规范化 | 统一 `Uuid::to_string()` 小写；大写/小写视为同一设备，不会分裂出两份数据 |
| 存库 | `groups.device_id`，索引 `idx_groups_device(device_id, created_at DESC)`；不返回给客户端，也不写日志 |

**本质**：设备号是 bearer 凭证——谁拿到谁就能读写这些文档。这是「无登录」阶段的取舍，不是安全边界。

## 2. 逐路由审计

| 路由 | 归属校验 | 跨设备行为 |
| --- | --- | --- |
| `POST /api/v1/groups` | 写入当前 `device_id` | 无越权面 |
| `GET /api/v1/groups` | `WHERE device_id = ?` | 只看到自己的组 |
| `GET /api/v1/groups/{id}` | `fetch_group(id, device)` | 404 |
| `PATCH /api/v1/groups/{id}` | 同上，且 `UPDATE ... AND device_id = ?` | 404 |
| `DELETE /api/v1/groups/{id}` | 同上，`DELETE ... AND device_id = ?` | 404 |
| `POST /api/v1/groups/{id}/pages` | 先 `fetch_group` 再落盘 | 404 |
| `PUT /api/v1/pages/{id}` | `JOIN groups ON g.device_id = ?` | 404 |
| `DELETE /api/v1/pages/{id}` | 同上 | 404 |
| `POST /api/v1/groups/{id}/render` | 先 `fetch_group` | 404 |
| `GET /api/v1/groups/{id}/status` | 先 `fetch_group` | 404 |
| `GET /api/v1/groups/{id}/docx` | 先 `fetch_group` | 404 |
| `POST /api/v1/groups/{id}/share` | 先 `fetch_group` | 404 |
| `DELETE /api/v1/shares/{token}` | `UPDATE ... WHERE group_id IN (SELECT id FROM groups WHERE device_id = ?)` | 404，撤销不掉别人的 |
| `GET /healthz` | 不鉴权 | 无业务数据 |

只读 Viewer（`/s/{token}/*`）只认 token：

| 路由 | 校验 |
| --- | --- |
| `GET /s/{token}` / `/state` | token 存在、未撤销、未过期 |
| `/img/{page_id}?v=thumb\|disp` | 同上，且页属于该 token 的组 |
| `/fig/{page_id}/{name}` | 同上 + 文件名白名单 `fig_<hex>.(png\|jpg)` |
| `/richtext/{page_id}?blocks=` | 同上 + `SELECT 1 FROM pages WHERE id=? AND group_id=?` |

**为什么用 404 而不是 403**：403 会告诉攻击者「这个 id 存在，只是不归你」，等于提供存在性探针。所有越权访问统一 `404 not_found`。

## 3. 数据边界

| 数据 | 隔离方式 |
| --- | --- |
| 组/页/块（SQLite） | 全部经 `groups.device_id` 间接限定；外键 `ON DELETE CASCADE`，删组即清页与块 |
| 文件树 `{data_dir}/g/{group_id}/…` | `group_id` 是 UUIDv4，不可枚举；所有外部取图都经 token 校验后再拼路径 |
| 识别缓存 `{data_dir}/ocr/v1-<sha256>/` | 按**图片内容**寻址：字节完全相同才命中，缓存内无 owner/时间/标题等任何用户信息。不构成跨用户数据泄露，但能推出「这张图以前被识别过」 |
| 分享 token | 22 位 hex（88 bit），`revoked`/`expires_at` 双重校验；不可枚举 |
| docx | 只经 `GET /groups/{id}/docx`（设备校验）产出，文件名用组标题，不含设备信息 |

## 4. 测试证据

`server/tests/isolation.rs`（3 个用例，全部通过）：

1. `other_device_cannot_touch_group_or_page`
   - B 对 A 的组发起 10 种操作（读、改名、删组、上传、渲染、状态、docx、建分享、删页、改页、撤销分享）→ 全部 404
   - B 的列表为空；A 的组仍可读；分享 token 未被 B 撤销，`/s/{token}/state` 仍 200
2. `device_id_is_canonicalized`
   - 大写设备号建组，小写读到同一份数据
   - `""` / `not-a-uuid` / 短 UUID → 401
3. `unknown_group_and_traversal_ids_are_not_found`
   - 合法但不存在的 UUID → 404
   - `..%2f..%2fetc` → 400/404，不出现 5xx

全量：43 个单测 + 6 个 API 集成 + 3 个隔离 + 1 个缓存集成，`cargo test` 全绿。

## 5. 剩余风险

1. **设备号即凭证**：泄露（日志、截图、备份、恶意应用读取 preferences）等同文档泄露，且无法吊销。
2. **不能跨设备**：换机/重装即丢数据，也没有「找回」路径——这是当前模型的结构性限制。
3. **分享链接无次数限制**：拿到链接的人可无限次读；只有过期与撤销。
4. **缓存命中可被推断**：知道某张图曾上传过（命中耗时 30ms vs 秒级），信息量极低但存在。
5. **DB 落盘明文**：`shiye.db` 里有 `device_id` 与全部文本，服务器被读即全泄露；依赖主机权限（`chmod 600`、独立用户）。

## 6. 后续加固（建议顺序）

| # | 项 | 做法 | 解决 |
| --- | --- | --- | --- |
| 1 | 设备号轮换 | `POST /api/v1/devices/rotate`：签发新号、旧号失效、组整体迁移 | 疑似泄露、设备转手 |
| 2 | 服务端下发设备号 | 首启调 `POST /api/v1/devices` 由服务端生成并入库，客户端只存返回值 | 客户端随机源不可信、便于审计与吊销 |
| 3 | 分享访问限制 | token 增加 `max_views` / 一次性 / 可选访问口令 | 链接外流的放大效应 |
| 4 | 账号体系 | 手机号/邮箱 + 设备绑定，多设备同步；设备号降级为「会话」 | 换机找回、真正多用户语义 |

前两项不改数据模型，只加接口与迁移；第 3 项改 `shares` 表；第 4 项是独立里程碑。
