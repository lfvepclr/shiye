# 拾页 / Shiye · 设计基线

- **文档编号**：202610181212-design
- **状态**：已定稿（v1）
- **定位**：连续拍摄多页纸质文档 → 端侧透视矫正与去阴影 → 百度 PaddleOCR 识别 → 生成 Word → 提供可查看、可分块复制的网页预览链接。

> ⚠️ 本文档会进入公开仓库。所有主机地址、域名、SSH 方式、AK/SK 一律以 `<HOST>` / `…` 占位，真实值只存在于服务器 `/etc/shiye/config.toml` 与本地 gitignored 的 `deploy/local.env`。

## 1. 已确认决策

| 项 | 决定 |
| --- | --- |
| 项目名 | 拾页 / Shiye（bundleName `com.shiye.app`，Rust crate `shiye-server`） |
| OCR | 百度智能云 PaddleOCR-VL 文档解析（`paddle-vl-parser` 异步任务 API），不自建模型 |
| 图像增强 | 端侧（ArkTS + ArkGraphics 2D），只上传处理后 JPEG（长边 ≤2000，q85，约 250KB/页） |
| 账号 | 无账号。客户端本地生成 `device_id`(UUIDv4)，通过 `X-Device-Id` 头归属文档 |
| 接口前缀 | `/shiye` 统一前缀：API 走 `/shiye/api/v1/*`，分享页走 `/shiye/s/{token}`；由 `config.toml` 的 `base_path` 控制 |
| 分享 | `/shiye/s/{22位随机token}` 只读、可设有效期、可撤销，不暴露 group_id |
| 服务端 | Rust / axum / tokio，`#![forbid(unsafe_code)]`，静态 musl 二进制 |
| 传输 | 目标主机有独立域名 → Caddy 自动 TLS，全站 HTTPS（富文本复制因此可用） |
| 版本目标 | compileSdk `26.0.0` / targetSdk `26.0.0` / compatibleSdk `6.0.0(20)` → 覆盖 HarmonyOS 6 与 7 |

## 2. 系统架构

```
┌─────────────── HarmonyOS 6 / 7 (ArkTS + ArkUI V2) ───────────────┐
│  相机(CameraKit) → 端侧处理(TaskPool: Skia 透视+去阴影) → 上传队列 │
│  Navigation 6 页 · LazyForEach 列表 · 本地 JSON 持久化 + 缩略图缓存 │
└───────────────────────────┬──────────────────────────────────────┘
                            │ HTTPS  /shiye/api/v1/*  multipart / JSON / 轮询
┌───────────────────────────▼──────────────────────────────────────┐
│  shiye-server (Rust, 单核小内存 VPS)                              │
│  Router::nest("/shiye")                                          │
│    ├─ /shiye/api/v1/*  ← 客户端（X-Device-Id 鉴权）               │
│    ├─ /shiye/s/*       ← 分享页（token 鉴权，只读）                │
│    └─ /shiye/healthz   ← 探活                                     │
│  axum ── 存储(SQLite WAL + 文件树) ── 任务队列 ── 百度 OCR 客户端   │
│                                       └→ docx 生成器              │
│  Web Viewer（内嵌单页，无框架，~50KB）                             │
└───────────────────────────┬──────────────────────────────────────┘
                            │ 每页一个异步任务
                    ┌───────▼────────┐
                    │ 百度智能云 API  │
                    └────────────────┘
```

**关键取舍**：百度 `paddle-vl-parser` 是「整档提交 → 整档返回」，天然拿不到逐页进度。**因此每张照片单独提交为一个 1 页任务**——这是「第 3/12 页识别完成、已完成的浮到前景」这个体验能成立的前提。

## 3. 用户动线

```
首页 ──[拍新文档]──▶ 相机页 ──(连拍 N 张)──▶ 组编辑页 ──[生成 Word]──▶ 进度页 ──▶ 完成页
  ▲                    │自动建组               │可选：单页编辑              │        │
  │                    │名="2026-10-18 11:33"  │四角矫正/增强强度          │        ├─ 下载 .docx
  └──── 返回 ───────────┴───────────────────────┴───────────────────────────┘        ├─ 复制分享链接
                                                                                     └─ 二维码 / 浏览器预览
```

**辅助动线**

1. 拍错了：缩略图条点任意一张 → 单页编辑 → 删除 / 重拍（回相机但保留组）。
2. 顺序不对：组编辑页长按 → 浮起 → 拖动 → 弹性让位 → 松手落位。排序即 Word 页序。
3. 中途退出：组以 `draft` 留在首页，卡片显示「N 页 · 未生成」，点回组编辑页。
4. 别人看：浏览器打开分享链接 → 单栏「原文 / 文本」→ 点块复制 / 长按多选 → 可下载 docx。

**组状态机**

```
draft ──[点生成]──▶ uploading ──▶ recognizing ──▶ done
  │                     │              │            │
  └──[删除]──▶ (gone)   └──[失败]──▶ failed ──[重试]──┘
```

## 4. 页面与交互规格

### P1 首页 `HomePage`

- 顶部品牌字「拾页」+ 右侧设置（服务器地址、关于）。
- 主 CTA：底部悬浮胶囊「拍新文档」（朱砂红 72vp，阴影 + 按压 scale 0.97）。
- 列表：`LazyForEach` 卡片流。每卡 = 左 88vp 首图缩略（圆角 12）+ 标题 / `12 页 · 今天 11:33` / 状态徽标（未生成 / 识别中 5/12 / 已完成）。
- 空态：一叠纸线性插画 + 「拍下第一份文档，它会自己变成 Word」。
- 交互：点击进组编辑页；左滑删除；长按进多选批量删除。

### P2 相机页 `CameraPage`

- 进入即建组：`title = "YYYY-MM-DD HH:mm"` 写本地；返回时若 0 页自动删组。
- 顶栏（悬浮玻璃条）：`✕ 关闭` / 组名 ▾（点击改名）/ `完成 (N)`。
- 取景：`XComponent` + `PreviewOutput`，`ImageFit.Cover` 铺满全屏；叠加三分构图网格（可关）、点击处 300ms 淡出的对焦框。
- 底部：相册导入 · 快门 72vp 白环 · 闪光灯 自动/开/关。
- 缩略图条：快门上方 96vp 横向滚动，最新一张从右侧 spring 滑入，末尾 `+N` 计数。
- 连拍不打断：按下即拍，无确认页、无全屏闪白；`inflight ≤ 2`，第 3 次点击排队。
- 手感：快门白环内缩 0.92 + 短促震动（`vibrator`）。
- 权限被拒：居中卡片解释 + 「去设置」，不静默失败。

### P3 组编辑页 `GroupEditPage`

- 顶部：返回 / 组名（可改）/ 选择。
- 主体：3 列 `Grid`，每格 `Image(file://thumb)` + 左上角页码角标（决定 Word 顺序）。
- 长按拖动排序：`Grid.editMode(true)` + `onItemDragStart/onItemDrop`；拖动中放大 1.06 + 阴影，其余格 180ms 弹性让位。落位后立即持久化 `pageOrder: string[]`（只存 id 数组，避免两份真值）。
- 底部：`+ 继续拍`（次要）/ `生成 Word`（主要，显示 N 页）。
- 多选态：勾选圈 + 底部「删除 (n)」。

### P4 单页编辑页 `PageEditPage`

- 全屏图（`ImageFit.Contain`）+ 四角手柄（28vp 白圆 + 朱砂描边，热区 44vp）+ 四块梯形半透明遮罩（`Polygon` 不支持挖洞，用四梯形拼出外部暗区）。
- 拖角时只移动覆盖层，不重算图像；`onActionEnd` 后 120ms 用 500px 低分辨率重算做实时预览。
- 底部玻璃工具条：旋转 90° · 重置四角 · 删除 · 增强强度滑杆 0~100（默认 60，`onChange` 结束 200ms 防抖）。
- 长按图片 = 看原图（松手恢复）——最直观的前后对比，不需要额外按钮。
- 右上 ✓ 保存：用 2000px 正式参数重算并落盘 `edit.jpg`。

### P5 进度页 `ProgressPage`

- 顶部：环形进度 + `正在识别 5 / 12`；副标题按阶段切换（正在增强… / 正在上传… / 正在识别…）。
- 主体纵向卡片流，每张卡片 = 该页增强图做背景 + 识别文本浮在前景：
  - 背景层：`Image` 全幅 + 白色 8% 蒙层（保文字对比度）。
  - 前景层：块文本列表，白底 88% 圆角卡片 + `backdropBlur`。
  - 未完成页：只有背景图 + 中央呼吸的「识别中」占位。
- 右上「背景」开关：关闭后全变纯白文本卡，滚动更省电。
- 完成时卡片依次 240ms cross-fade，然后自动跳完成页（可关）。
- 退后台：不持有长时任务（百度识别可能几分钟无流量，会被系统判低速而取消）；回前台立即拉一次状态对齐。

### P6 完成页 `ResultPage`

- 顶部 ✓ 大图标 + `《组名》已完成 · 12 页`。
- 三张操作卡：下载 Word（`DocumentViewPicker.save()` 直写）/ 复制链接（剪贴板 + toast）/ 二维码（ArkUI 内置 `QRCode`）。
- 底部次级链接：在浏览器中预览（`want` 拉起系统浏览器）。
- 分享设置：7 天 / 30 天 / 永久 + 撤销链接。

### 视觉与动效规范

- 色彩：宣纸白 `#FAF8F4` 底 / 卡片 `#FFFFFF` / 墨黑 `#1A1A1A` / 次要 `#6B6560` / 朱砂主色 `#C8412F` / 分割 `#E8E2D8`。
- 形态：圆角 16（卡片）/ 20（按钮）/ 12（缩略图）；阴影 `0 8 24 rgba(26,26,26,0.06)`。
- 字体：HarmonyOS Sans；页码与进度用 tabular numerals 防跳动。
- 材质：API ≥ 26 用 `uiMaterial.Material` 沉浸光感；API 20~25 降级为 `#CCFFFFFF` + 1px `#33FFFFFF` 描边（统一走 `common/ApiVersion.ets` 门控）。
- 动效：进入 `cubic-bezier(0.2,0.8,0.2,1)` 240ms；按压 120ms；让位 `spring(mass 1, stiffness 320, damping 28)`。
- 触觉：快门 / 排序落位 / 生成完成，三处震动。

## 5. 客户端技术方案

### 5.1 关键选型

| 议题 | 选型 | 理由 |
| --- | --- | --- |
| 相机 | 自建 `XComponent` + CameraKit（不用 `cameraPicker`） | 只有自建能连拍不打断 + 自定义缩略图条 + 页数角标 |
| 取图 | `photoOutput.capture()` + `on('photoAvailable')` → `getComponent(JPEG)` → `ArrayBuffer` | 不写相册，省掉 `WRITE_IMAGEVIDEO` 权限与整条 IO 链路 |
| 透视矫正 | `drawing.Matrix.setPolyToPoly(src4, dst4, 4)` + `drawing.Canvas(pixelMap)` | 本机 SDK 已确认存在（API 12+），走 Skia，单页 ~30ms |
| 去阴影 | 低分辨率光照图 + `BlendMode.MULTIPLY` 补偿层 | 全程 Skia 无逐像素循环；`out = I × (255/L)^s`，`s` 直接绑强度滑杆 |
| 状态管理 | V2（`@ComponentV2`/`@Local`/`@Param`/`@ObservedV2`/`@Trace`） | 每页独立高频状态，V2 属性级观测只刷那一张卡 |
| 路由 | `Navigation` + `NavPathStack` + `navDestination` | Router 已淘汰 |
| 列表 | `LazyForEach` + 自研 `IDataSource`（`onDataAdd/Delete/Move/Change`） | 排序/追加是增量操作，禁止 `onDataReloaded()` |
| 缩略图 | 自研两级缓存（磁盘 320px + 内存 LRU 60），UI 用 `Image('file://…')` | `Image(pixelMap)` 把位图生命周期绑到组件，滑动必 OOM |
| 进度 | 轮询 `/status`，1s 起 ×1.4 退避到 8s | `@ohos.net.http` 无 `dataReceive` 事件，做不了 SSE |
| 上传 | 手拼 multipart（`Uint8Array`），每页一请求，并发 2 | ArkTS 无 FormData；单页 250KB 便于失败只重传一页 |
| 后台 | 上传阶段用 `DATA_TRANSFER`；识别等待阶段不持任务 | SDK 注释：DATA_TRANSFER 超 10 分钟无进度会被系统取消 |
| 下载 | `DocumentViewPicker.save()` → `fs.writeSync` | 用户能找到文件 |
| 二维码 | ArkUI 内置 `QRCode` 组件 | 零依赖零权限 |

### 5.3 P0 技术验证（Go/No-Go）

| # | 验证项 | 失败后果 | 备选 |
| --- | --- | --- | --- |
| P0-1 | `drawing.Canvas`/`Matrix` 能否在 TaskPool 线程用；`setMatrix(透视)` 后 `drawImage` 是否真做透视（非降级成仿射） | 单页编辑要换实现，+2 天 | 纯 ArkTS 逆映射（`squareToQuad` 闭式解 + 双线性采样），2000px 约 150~400ms |

| P0-3 | 手拼 multipart 打到本地 mock，20 页 × 250KB 稳定，服务端字节完整 | 图片损坏 | 改 base64 JSON（体积 +33%，不推荐） |

### 5.5 性能红线

| 风险 | 规避 |
| --- | --- |
| 4000×3000 RGBA = 48MB，连开 3 页 OOM | 一律 `createPixelMap({desiredSize})` 解码即降采样；编辑 1000px、导出 2000px；`release()` 放 `finally` |
| 缩略图用 PixelMap 塞列表 | UI 只用 `Image('file://…')`；磁盘 320px；LRU ≤ 60 项 |
| 主线程做透视/编码 | 全进 TaskPool，`setTransferList` 零拷贝；重任务信号量并发 1 |
| 进度页每秒整页重建 | `@Trace` 只标 `status`；`onDataChange(index)`；卡片背景用 600px 小图 |
| 边拍边后台 warp | 拍照回调只入队不计算；`inflight ≤ 2`；缩略图延后到「拍摄暂停 300ms」 |

## 6. 服务端技术方案

### 6.1 依赖

`axum 0.8` · `tokio` · `tower-http`（static/compression/trace/limit）· `sqlx`(sqlite, bundled) · `reqwest`(rustls) · `image` · `docx-rs` · `serde`/`serde_json` · `uuid` · `sha2` · `base64` · `thiserror` · `tracing`。

根模块首行 `#![forbid(unsafe_code)]`。

### 6.2 数据模型（SQLite WAL，`busy_timeout=5000`）

```sql
groups(id TEXT PK, device_id TEXT NOT NULL, title TEXT, state TEXT,
       page_count INT, done_count INT, created_at INT, updated_at INT,
       docx_rev INT, error TEXT)
pages (id TEXT PK, group_id TEXT NOT NULL, ord INT, status TEXT,
       w INT, h INT, ocr_ms INT, error TEXT)
blocks(page_id TEXT NOT NULL, ord INT, label TEXT, text TEXT,
       x1 REAL, y1 REAL, x2 REAL, y2 REAL, poly TEXT)
shares(token TEXT PK, group_id TEXT, expires_at INT NULL, revoked INT)
settings(k TEXT PK, v TEXT)
```

文件树：`{data_dir}/g/{group_id}/{page_id}/{raw.jpg,edit.jpg,disp.jpg,thumb.jpg}` + `blocks.json` + `docx/{rev}.docx`。

识别缓存：`{data_dir}/ocr/v1-<sha256(edit.jpg)>/{result.json,figs/}` —— 百度 OCR 按次计费，同一张图重传/换组/重试直接命中缓存，不重复计费；超过 500 条按最近使用淘汰。

所有 id 用 UUIDv4（不用秒级时间戳，避免碰撞与枚举）。

### 6.3 API 契约

所有路由挂在 `Router::nest("/shiye", …)` 下，前缀取自 `config.toml` 的 `base_path`。

**身份与隔离**：无账号体系，客户端首启生成 UUIDv4 设备号（存 preferences），随 `X-Device-Id` 提交；服务端校验并小写规范化，缺失/非法 401。`/api/v1/*` 全部按 `device_id` 过滤，跨设备访问统一 404（不用 403，避免泄露存在性）。分享 token（88 bit、可撤销/过期）是唯一跨设备只读凭证，Viewer 只按 token 取数。识别缓存按内容哈希共享，不含用户标识。设备号即 bearer 凭证，泄露等同文档泄露——后续如需多设备同步/找回，必须引入账号体系而不是共享设备号。回归测试见 `server/tests/isolation.rs`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/shiye/healthz` | 健康检查（不鉴权） |
| POST | `/shiye/api/v1/groups` | 建组 `{title}` → `{id,title}` |
| PATCH | `/shiye/api/v1/groups/{id}` | 改名 / 改页序 `{title?, page_order?}` |
| GET | `/shiye/api/v1/groups` | 本设备组列表（`X-Device-Id`） |
| GET | `/shiye/api/v1/groups/{id}` | 组详情（含每页状态，断点续传用） |
| POST | `/shiye/api/v1/groups/{id}/pages` | multipart `ord, file` → `{page_id}` |
| DELETE | `/shiye/api/v1/pages/{id}` | 删页 |
| POST | `/shiye/api/v1/groups/{id}/render` | 启动识别 → `{state:"queued"}` |
| GET | `/shiye/api/v1/groups/{id}/status` | `{state,done,total,pages:[…]}` |
| GET | `/shiye/api/v1/groups/{id}/docx` | 下载 docx |
| POST | `/shiye/api/v1/groups/{id}/share` | `{expires_in}` → `{url,token}` |
| DELETE | `/shiye/api/v1/shares/{token}` | 撤销 |
| GET | `/shiye/s/{token}` | Web Viewer（只读 HTML） |
| GET | `/shiye/s/{token}/state` | Viewer 数据 |
| GET | `/shiye/s/{token}/img/{page_id}?v=thumb\|disp` | 受控图片（校验 token 归属） |
| GET | `/shiye/s/{token}/richtext/{page_id}` | `{html,text}` — Word 友好富文本 |

**三组路由的鉴权边界**

- `/shiye/api/*` —— 客户端专用，中间件校验 `X-Device-Id`，只能访问本设备的组。
- `/shiye/s/*` —— 分享链接专用，中间件校验 `token`（存在、未撤销、未过期），只读。
- `/shiye/healthz` —— 无鉴权，供探活 / 反代使用。

**Viewer 内所有前端请求一律用相对路径**（`./state`、`./img/…`、`./richtext/…`），这样 base_path 改成什么、反代怎么改写都不会拼错地址。

### 6.4 OCR 流水线

```
render → 每页 tokio::spawn（Semaphore(2)，百度 query QPS 上限 5）
  1. 取 token（30 天缓存，提前 1 天续期，落 settings 表）
  2. POST /paddle-vl-parser/task {file_data(base64), file_name,
                                  relevel_titles:true, merge_tables:true, recognize_seal:true}
  3. 每 3s POST /task/query，status=success → parse_result_url
  4. 下载 JSON → 适配 blocks（position[x,y,w,h] → bbox[x1,y1,x2,y2]，label 映射）
  5. 表格 markdown 里远程 <img> 下载本地化；figure 的 data_url 下载落盘
  6. HTML 白名单清洗（防 XSS）→ 写 blocks 表 → done_count++ → 状态即变
重试：网络/5xx 重试 2 次（2s/6s 退避）；4xx 直接 fail 并保留错误文案
```

### 6.5 Word 生成（docx-rs）

- 每页按 `ord` 输出，页间 `PageBreak`。
- `doc_title`/`paragraph_title` → `HeadingLevel`（`sub_type` 尾位数字定级；`1.`/`1、` 开头降 H3，避免整篇塌成 H1）。
- `table` → 解析 OCR 的 HTML 表格 → `docx-rs Table`（`Table Grid`）；单元格内 `<img>` 单独成段。
- `image`/`chart`/`seal` → 内嵌 `Pic`，宽度按 bbox 占比换算，上限 5 英寸。
- 公式：LaTeX → Unicode（Rust 版简化符号表，覆盖常用 200 项）。
- 字体：正文「等线」11pt，标题「黑体」，行距 1.4。
- 单页 < 100ms，20 页 < 3s。

### 6.6 Web Viewer

- 挂载在 `/shiye/s/{token}`，单文件 HTML（`include_str!` 内嵌），原生 JS ~600 行，无框架无 CDN。
- 移动端单栏，顶部「原文 / 文本」切换：
  - 原文：`<img>` + 双指缩放 + 块边框高亮（点文本块 → 原图对应区域闪一下）。
  - 文本：块列表，左上角类型标签（标题/正文/表格/图片/印章）。
- 复制：点块 → 块下方浮出「复制」（锚定块，而非 `fixed` 右上角）；长按进多选。
  - 纯文本：`navigator.clipboard.writeText`，失败回退 `textarea + execCommand`。
  - 复制到 Word：`GET ./richtext/{page_id}?blocks=1,5,7` → `ClipboardItem({'text/html','text/plain'})`。
  - 全站 HTTPS → 富文本复制为默认路径；若退回 HTTP，自动降级为纯文本复制。
- 首屏只加载 `thumb` + 文本；点「看原图」才加载 `disp`（1600px）。图片 `Cache-Control: immutable`。
- 分享链接按 `public_base_url` 拼接，不硬编码域名。

### 6.7 低配主机资源纪律

- 单进程 tokio，`worker_threads = 2`。
- 图片流式处理：解码前先读 header 判尺寸，超 25MP 直接拒绝。
- 百度任务并发 2，内存峰值 < 150MB。
- 请求体上限 6MB（`RequestBodyLimitLayer`）。
- 磁盘：原图保留，`disp`/`thumb` 派生；docx 只留最新 `rev`，旧 rev 异步清理；软限 80GB。

## 7. 部署形态

```
/usr/local/bin/shiye-server  # 静态 musl 二进制 ~15MB
/etc/init.d/shiye            # OpenRC（Alpine 无 systemd）
/etc/shiye/config.toml       # 真实配置（600，不进仓库）
/var/lib/shiye/              # 数据
```

```toml
listen          = "127.0.0.1:8080"     # 由反代转发，不直接暴露公网
base_path       = "shiye"
public_base_url = "https://<HOST>"
data_dir        = "/var/lib/shiye"
share_ttl_days  = 30

[baidu]
api_key    = "…"
secret_key = "…"
```

Caddy 自动 TLS。带宽预算（上行 ~3 Mbps ≈ 375 KB/s）：

| 动作 | 体积 | 耗时 |
| --- | --- | --- |
| 上传一页 | 250KB | 视客户端网络 |
| Viewer 首屏（HTML 50KB + 20×25KB 缩略 + 文本 30KB） | ~580KB | 1.6s |
| 看一页原图（1600px） | 250KB | 0.7s |
| 下载 12 页 docx | ~4MB | 11s |

> Viewer 默认不加载原图、列表只用缩略图，是这套带宽下唯一可行的做法。

## 8. 敏感信息边界

**不进仓库**：主机 IP / 域名 / SSH、百度 AK/SK、`/etc/shiye/config.toml`、`deploy/local.env`、`rawfile/config.json`。

**可以进仓库**：代码、`config.toml.example`、`.agent/` 文档（`<HOST>` 占位）、OpenRC 脚本、Caddyfile 模板（`{$SHIYE_DOMAIN}`）。

提交前自检：

```bash
grep -rniE '([0-9]{1,3}\.){3}[0-9]{1,3}|secret_key|BEGIN .*PRIVATE KEY' . --exclude-dir=.git
```
