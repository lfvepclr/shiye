**S0 结论**

1. **本机编译完全正常**，`cargo build` / `cargo test` 均通过。之前拉不到依赖是**全局 `~/.cargo/config.toml` 里配了已废弃的 rsproxy git 索引**（`https://rsproxy.cn/crates.io-index/`），仓库内新增 `.cargo/config.toml` 用 `sparse+https://rsproxy.cn/index/` 覆盖即可（与 Phantom 项目同一做法）。
2. 目标主机 x86_64 + Alpine 3.18.3，SSH 免密可用；但**没有 cargo、没有 swap、可用内存约 460MB** → 不在服务器上编译，只跑二进制。
3. 交叉编译**必须带 C 工具链**：`cargo build --target x86_64-unknown-linux-musl` 配 `linker = "rust-lld"` 会在 `libsqlite3-sys` 处失败（`cc-rs` 找不到 `x86_64-linux-musl-gcc`）。原因是我们依赖树含 C：SQLite 的 bundled 源码，后续 `reqwest`+`rustls` 还会引入 `ring`/`aws-lc-rs` 的 C 与汇编。
   → 采用 `cargo zigbuild`（zig 的 `cc` 能产 musl 目标码）。
   → Phantom 之所以只用 `rust-lld` 就够，是因为它刻意保持纯 Rust 依赖（TLS 用 RustCrypto 而非 ring，存储无 SQLite）。
4. 主机**没有 Caddy** → S8 需先装（`apk add caddy` 或官方静态二进制）。

**验收**：`git log` 有一条 commit，`git remote -v` 指向 origin，`~/.workbuddy-ai/skills/harmonyos-development/SKILL.md` 存在。
